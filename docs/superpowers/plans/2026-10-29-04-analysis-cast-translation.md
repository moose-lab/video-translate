# Analysis, cast and translation implementation plan

> **For agentic workers:** REQUIRED: superpowers:subagent-driven-development and test-driven-development. Execute one implementation task at a time. Each task receives independent specification review followed by quality review before its successor. This is approved product scope; do not ask for per-task permission.

**Goal:** Make an uploaded source produce editable, correctly timed source/cast data and independently editable target translations through remote services. Preserve the original result and every manual correction. This increment prepares the real inputs required for per-line cloning; it does not declare the full product complete.

**Architecture:** Add project-owned domain records and service functions beside the existing execution engine. APIs perform short authenticated transactions; independent workers perform CPU media work and remote inference. Existing named input fingerprints arbitrate freshness. Translation text, transcripts and private media stay outside the bounded event journal.

**Sources:** Approved SaaS design and `../specs/2026-10-29-dubbing-domain-contract.md`. The latter fixes entity, API, history, timing and selective invalidation semantics. Provider adapters and structured capabilities from increment3 must pass both reviews before implementation starts. Do not copy VoiceStudio application code or install local AI packages.

## Existing interfaces and constraints

- Python sources are under `src/videotranslate/`; tests use the app factory and `client_factory`/`register` fixtures. Run with `PYTHONPATH=src uv run --frozen --extra dev pytest ...` because this machine may ignore a hidden editable-install path file.
- `Project` in `models/core.py` has workspace, revision, immutable source-asset reference, source audio ordinal, source language, target tags and settings. `owned_project` excludes deleted/foreign projects. `Asset` content reads are authorized; do not return storage keys or paths.
- `execution.inputs.lock_project` establishes project-first lock order, then `set_inputs` updates exact facet fingerprints and invalidates consumers. `append_event` supplies ordered project events; facts contain IDs/counts/hashes only. Project revision is lineage and must not become a global conflict for unrelated timeline cells.
- `StageDefinition(name, validate_options, resolve_inputs, handle, publish)` has a short transactional publisher. `RunContext` checks active lease/current input and persists begin/record remote submission; `StageResult.facts` is publicly returned and limited to64KiB. Do not put private raw provider payloads, dialogue or local paths in facts.
- Existing remote clients: HF Router `translate`/`transcribe`; OmniVoice and Demucs `submit_*`/`poll_*` with real saved Gradio event IDs and host/prefix; NVIDIA file streaming has no durable ID and must distinguish uncertain submission. Use the final increment3 signatures/capability contract. Credentials resolve server-side from the workspace vault and never enter run options, result JSON or events.
- The API and browser preview currently retain user state under `/tmp/videotranslate-setup-preview`. Do not clear, replace or inspect any real credential. Tests and review use isolated databases and fake tokens. No inference is inferred from metadata checks.

## Task 4A: Source selection, immutable editing and manual language tracks

This task is one coherent domain foundation. It implements all data and manual editing/import routes below without registering a pretend cloud stage. Voice reference media and remote jobs belong to4B/4C.

### File map

- `models/dubbing.py` and migration`0004_dubbing_domain.py`: source selections/tracks, immutable transcript and segment revisions, stable segment IDs, cast, target tracks/context/translation revisions/current states.
- `dubbing/contracts.py`: strict bounded requests and public response types.
- `dubbing/ownership.py`, `source.py`, `segments.py`, `speakers.py`, `translations.py`, `timeline.py`: focused project-scoped operations, history and facet changes.
- `dubbing/subtitles.py`: pure SRT/VTT/numbered-text import parser, safe text normalization and explicit alignment previews.
- `routes/dubbing.py` or focused route modules: authenticated API registration in app factory.
- `tests/test_dubbing_domain.py`, `test_dubbing_edits.py`, `test_dubbing_imports.py`: meaningful ownership, concurrency/history, mapping and invalidation regressions.
- `docs/engineering/dubbing-verification.md`: actual RED/GREEN, migration and contract evidence, with unimplemented stages explicit.

### Required behavior

- [x] Write RED tests for a successful real-probe-based source selection and invalid ordinal/window/source lineage. Selection includes `{revision,source_asset_id,audio_ordinal,start_ms,end_ms}`; missing end resolves to probed end, not a provider's maximum. Reject nonfinite, reversed, empty, negative and out-of-duration bounds. Probe facts are taken only from a fresh successful run for the currently owned asset. Store both ordinal and absolute stream index with actual probe provenance. A selection change invalidates derived analysis/timeline while preserving historical data; full-video probe remains reusable.
- [x] Add database models and self-contained additive migration. Enforce ownership with composite project/workspace foreign keys, and composite references for rows crossing domain tables. IDs supplied by clients cannot cross projects even inside the same workspace. Revision history is immutable after creation; current-pointer updates are compare-and-swap. A project-owned source-state row may hold current selection/transcript; avoid an unvalidated project JSON blob containing all timeline history. Test metadata/migration parity and foreign-reference rejection.
- [x] Implement `PUT /api/projects/{id}/source-selection`, `GET /api/projects/{id}/timeline?target_language=&limit=100&offset=0` and bounded `GET` history routes for source/transcript/segment revisions. Timeline returns source identity/window, active transcript lineage/stale state, one source page, selected target's matching translations, cast summaries and target-track summaries. No all-target Cartesian expansion or unbounded nested histories. Current source times are relative to the window; raw imported/original source text remains separately available.
- [x] Implement stable manual source editing: `POST /segments`, `PATCH /segments/{id}`, `POST /segments/{id}/split`, `POST /segments/merge`. Creation can initialize an explicitly manual transcript for a valid source selection. Requests carry relevant source/row revisions. Validate text lengths, finite integer milliseconds, nonempty ordered intervals within the window and current owned speakers. Different-speaker overlap is allowed. Split/merge require explicit current IDs/revisions/text/time/role distributions, preserve parent lineage and archive replaced segments instead of erasing originals. Never guess word timing or speaker assignment. Two concurrent edits of one row yield one success/one409; unrelated rows can both succeed.
- [x] Implement `POST /speakers`, `PATCH /speakers/{id}`, `POST /speakers/merge`. Work labels are editable and cannot assert real identity. Binding and merge operations retain old revisions and archive merged labels; merge updates affected current segment bindings atomically. A name-only edit emits an event without changing translation/audio dependencies. Archived/historical/foreign speakers cannot bind active segments.
- [x] Add pure bounded SRT/VTT parsing and `POST /source/import/preview`, `POST /source/import/apply`. Strip/ignore styling and external-resource markup as data; never evaluate caption contents. Preserve CJK/RTL/combining characters and meaningful line breaks. VTT voice labels may create work labels; unlabelled captions stay unassigned. Preview is read-only and returns ordered cue IDs, timing errors, proposed mapping and explicit conflicts. Apply uses a canonical preview digest plus current selection/transcript revisions; conflicting/replayed-under-changed-source mappings are rejected. Explicit replace/new-transcript mode preserves old source history. Do not silently zip mismatching count/timing onto existing segment IDs.
- [x] Implement `POST /language-tracks`, `PATCH /language-tracks/{tag}` with preserved catalog variants, Fast/Cinematic/Autofit mode, immutable supplied context/glossary snapshots and row CAS. Keep project target tags and track records coherent; Auto cannot be a target. Existing declared targets are lazily materialized safely or created together without GET side effects. Track removal/archive keeps historical rows and does not corrupt other targets.
- [x] Implement manual `PATCH /language-tracks/{tag}/segments/{segment_id}`, target import preview/apply and `POST /language-tracks/{tag}/approve`. Store immutable translation revision with exact source-text fingerprint, provenance, context/mode and parent. Current state has row revision/lock/approval/stale. Source meaning changes stale the corresponding target translations even when locked, retaining visible wording; reapproval records the new source lineage. Timing-only or speaker-name edits do not stale translated meaning. One target's edits never overwrite another. Reimport/retranslation cannot replace a locked row without an explicit audited force option.
- [x] Facets: source asset/track/window; `segment.{id}.text`, `.timing`, `.voice`; target-specific translation keys; per-target context/glossary/mode. A text edit affects only that segment's translations and descendants; timing edits preserve natural TTS, but invalidate fit/reference cuts/subtitles; speaker binding affects voice descendants; name-only and unrelated-target edits leave unaffected keys intact. No-op edits do not manufacture changed dependencies. Existing run/probe tests must keep passing.
- [x] Every mutation uses authenticated workspace/project scope, CSRF and relevant row CAS. Consistent404 for foreign/deleted/historical current-edit targets;422 for invalid requests,409 for actual revision/mapping conflicts. Publish actual edit/import/merge/lock/reapproval events with bounded safe facts. Do not serialize dialogue into the event journal or return SQL exception strings.
- [x] Verify complete Python suite, Ruff/format/compile, live temporary PostgreSQL upgrade/downgrade/upgrade and metadata parity. Demonstrate actual simultaneous row edits (not just sequential status simulation), cross-workspace and same-workspace cross-project denial, immutable originals, split/merge ancestry, explicit import conflicts and exact facet invalidation. - [x] Register separate `extract`, `separate`, `transcribe` durable stages. Each has exact input keys and independent transactional publication. Demucs submits one named call, durably saves its actual event ID/host and resumes that ID; keep distinct vocals/instrumental assets with decode/duration/channel validation. NVIDIA uses the English file contract and rejects unsupported language/oversize windows before submitting. Optional HF timestamped ASR may explicitly return no diarization; missing role labels require manual review, never invented speakers. Auto only uses an actually capable detector. Original provider text/speaker/times are preserved in immutable transcript revisions.
- [x] Implement `POST /projects/{id}/workflow` with durable prerequisite orchestration and explicit stages/checkpoints. Repeated action is idempotent for the same selection/input; do not enqueue duplicate paid work. Default pauses at source/cast review; auto_advance never hides missing references/role/timing/capability issues. Only implemented workflow actions are accepted. API status reflects real runs, not a fabricated percentage. Failure/restart tests prove already submitted jobs and completed sync results are recovered appropriately.
- [x] Implement private voice references: extract explicit source/vocal spans or upload bounded audio, validate by CPU decode/probe, hash and store actual source asset/absolute bounds/relative bounds/text/language/speaker/version. Immutable text-correction versions share owned audio safely. Support speaker default reference and explicit per-segment reference bindings; time/text/source edits mark derived references stale while preserving independent uploads. Record measured too-short/mixed-overlap flags; do not claim noise or clean single-speaker confidence without evidence. No silent trimming with unchanged transcript. Default/override change invalidates affected voice keys only.
- [x] Tests use contract doubles only in tests and real CPU fixtures; actual cloud inference is performed separately after configured credentials/services and the product path exist. Verify migrations/PostgreSQL/isolation/restart/cleanup, full suite and both independent gates.
